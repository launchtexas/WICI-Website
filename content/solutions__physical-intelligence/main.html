The WiCi approach

On-site GPU inference
for robots.

A shared GPU on the premises, one wireless hop from every robot, over a link designed for robot traffic.

Datacenter GPUs provide capacity. On-robot processors provide deterministic latency and keep data local. An on-site GPU provides both: a full-size GPU, shared with every device in the building, with no handoffs, no shared internet links, and no internet in the control loop. Data stays on the premises. Worst-case latency is one wireless hop.

WiCi delivers this as one system. WiCi One is the on-premises GPU. The Overview presents it to the robot as a local GPU over standard Wi‑Fi, at a measured ~1.5 ms base round trip. The WiCi Wireless Chip is the robot-side radio, so both ends of the link run on one schedule.

Requirements for a robot wireless link

Reliable off-robot inference requires the access point and the robot radio to be designed together.1 The WiCi stack is designed to these four requirements.

  • Scheduled, uplink-first access. Each robot is assigned a fixed transmission slot instead of contending for the channel, and the link is designed for the upstream video traffic that standard Wi‑Fi is not.
  • Common time base. Frames are captured and transmitted on one clock, so the GPU processes them on arrival without queuing.
  • No handoffs, clear spectrum. One site, one GPU, one hop, on wide uncongested channels with data duplicated across links, so nothing is handed off or retransmitted.
  • No site modifications. The GPU includes its own link. Existing Wi‑Fi and customer networks are unchanged.

Add compute without site modifications.

Warehouse robots keep inference on-robot to avoid changes to customer networks, at the cost of smaller models and an underutilized processor in every unit.
